01 · Product decision

Executive summary

Lekhoni's primary USP is Roman-to-native Unicode writing. A writer selects Bengali phonetic or Hindi phonetic input, types the language with familiar English/Roman letters, chooses or accepts the intended word, and stores real বাংলা or हिन्दी Unicode directly in the document. That text can be copied, shared through the browser/operating-system share sheet, or exported to common publishing formats without a proprietary font or encoding.

Transliteration—not language translation Typing ami banglay likhi and producing আমি বাংলায় লিখি changes the writing system while the language remains Bengali. 03A · Primary product advantage

Type in English letters. Publish in Bengali or Hindi Unicode.

The shortest path through Lekhoni is intentionally simple: choose a phonetic language, type the words as they sound using a Roman keyboard, confirm the native-script candidate, and share standards-based Unicode that works outside the application.

Bengali phonetic input

Roman input ami banglay likhi

Stored Unicode আমি বাংলায় লিখি

The editor stores Bengali characters, not the Roman spelling and not glyphs from a proprietary legacy font.

Hindi phonetic input

Roman input main hindi mein likhta hoon

Stored Unicode मैं हिंदी में लिखता हूँ

The editor stores Devanagari Unicode that can be searched, copied, exported, indexed, and rendered by standards-compliant software.

The language stays Bengali or Hindi “English script” describes the keyboard/input letters only. Lekhoni performs phonetic transliteration into Bengali or Devanagari script; it does not convert the meaning into English or another language. The UI consistently uses phonetic typing, script conversion, or transliteration rather than “translate.”

Core user journey

1 · Choose

Select Bengali phonetic, Hindi phonetic, or Native/English. Lekhoni never guesses the intended language.

2 · Type

Enter a Roman word or short phrase. The active token remains a visible composition buffer while candidates are calculated locally.

3 · Commit

Press Space/Enter for the top candidate, use number/arrow keys for another candidate, or keep the Roman text. One Undo restores the prior state.

4 · Publish

Copy, use the system share sheet, or export. Every route starts from the same canonical native Unicode document.

Unicode invariants

  • Canonical editor content uses real Bengali and Devanagari Unicode code points; no Bijoy/Krutidev-style legacy encoding and no glyph substitution as data.
  • Committed text is normalized to NFC at a controlled boundary while the active Roman composition buffer remains unchanged and visible.
  • Caret, selection, deletion, candidate ranges, statistics, and tests are grapheme-aware and cover conjuncts, matras, nukta, ZWJ/ZWNJ, emoji, and mixed scripts.
  • Every commit is one undoable editor transaction; the original Roman token can be restored or intentionally kept.
  • Bengali uses lang="bn", Hindi uses lang="hi", and mixed runs retain language metadata for accessibility and export.
  • Sharing is always an explicit user action with a preview. Lekhoni never posts content automatically.

05 · System view

High-level design

The design follows clean boundaries: presentation depends on application facades; facades depend on domain contracts; browser and package details live behind adapters.

External context

Architectural principles

Single responsibility

Editor, assets, imports, research, citations, proofing, storage, backup, language packs, and PWA updates have separate services and adapters.

Open/closed

New work modes, document nodes, metadata providers, repositories, exports, and language engines implement stable contracts.

Liskov substitution

In-memory test repositories and future remote repositories honor the same observable behavior.

Interface segregation

Small read/write/search/snapshot ports avoid a single browser-storage god service.

Dependency inversion

Facades depend on repository and engine interfaces, never Dexie or browser globals directly.

Progressive enhancement

Core writing works everywhere; install, folder linking, and persistent storage improve when supported.

06 · Behavior

Runtime flows

Editing and autosave sequence
  1. ProseMirror emits a document transaction.
  2. EditorFacade updates its signal state immediately and sets save state to editing.
  3. A 500–800 ms debounce collapses rapid edits.
  4. SaveDocumentUseCase compares the expected revision with the repository revision.
  5. DexieDocumentRepository writes content and metadata in one transaction, increments revision, and updates the recovery snapshot policy.
  6. The facade announces saved and publishes the revision through BroadcastChannel.
  7. A stale revision creates a conflict copy; it never overwrites silently.
Primary USP — Roman input to native Unicode and direct share
  1. The writer explicitly selects Bengali phonetic or Hindi phonetic; the choice is attached to the editor session and caret, never inferred silently.
  2. Roman keystrokes build an ephemeral composition token. Already committed document content remains unchanged while UnicodeComposerFacade sends the bounded token and local context hint to language.worker.
  3. The worker ranks local translation memory, reviewed colloquial mappings, licensed Roman/native pairs, language-specific rules, and the formal Sanscript fallback.
  4. The caret popup displays native candidates, the original Roman token, provenance/confidence labels, and keyboard shortcuts. A stale response is discarded by request ID and document revision.
  5. Space, punctuation, Enter, a number/arrow selection, or pointer choice commits one candidate as NFC Bengali/Devanagari text plus lang metadata in one ProseMirror transaction. Keep Roman commits the original token.
  6. Undo restores the exact pre-commit composition; accepted corrections may be saved to local user memory only after explicit consent.
  7. Copy/Share serializes the selected scope from canonical editor JSON, previews the exact payload, then uses Clipboard or Web Share only after the writer acts. Unsupported share targets fall back to copy or file download.
Language lookup sequence
  1. User selects source, target, scope, and invokes lookup.
  2. LanguageAssistantFacade derives plain text and sends a request ID to language.worker.
  3. The worker normalizes Unicode and segments text without changing the source.
  4. Ranking checks user memory, curated phrase, direct exact entry, alias, limited fuzzy candidate, then an English-sense pivot.
  5. The worker returns candidates with match type, source, confidence band, and unmatched ranges.
  6. User explicitly chooses Replace, Insert, Copy, Save correction, or Cancel.
Application update sequence
  1. Angular service worker detects a versioned release.
  2. UpdateFacade shows a nonblocking update notification.
  3. Before activation, the active document is saved and snapshotted.
  4. The user activates the update, or the app waits until no document is dirty.
  5. The application reloads; database migrations run before editing is enabled.
  6. If migration fails, recovery mode permits backup export and blocks destructive writes.
Language-pack update sequence
  1. Fetch the small manifest when online and compare semantic versions.
  2. Download the content-hashed candidate pack to temporary storage.
  3. Verify declared size, schema version, and SHA-256 digest.
  4. Import and run smoke queries in a worker.
  5. Atomically mark the new version active and retain the prior version for rollback.
  6. Remove the older pack only after the next successful application start.
Backup and restore sequence
  1. Open a consistent read transaction and build a versioned manifest of records and referenced assets.
  2. Hash JSON payloads and asset bytes, then stream a .lekhoni ZIP in an archive worker.
  3. Validate the generated manifest against the same strict schema used for restore.
  4. During import, reject unsafe paths, excessive counts/sizes/compression ratios, malformed records, and hash mismatches before database writes.
  5. Preview counts and conflicts; user chooses merge, duplicate, replace, or cancel.
  6. Apply changes transactionally and create a pre-import recovery snapshot.
Rich document import and asset sequence
  1. User selects DOCX, HTML, Markdown, or text and chooses the destination mode/template.
  2. The import worker checks extension, magic bytes, declared/decompressed size, nesting, and time limits.
  3. DOCX is converted to semantic HTML with external-file access disabled; Markdown is parsed to HTML; raw HTML begins at the sanitizer.
  4. DOMPurify applies a strict tag/attribute/URL policy, then the ProseMirror parser accepts only the owned schema.
  5. Embedded images are validated, hashed, deduplicated, and staged as Blob assets; references use asset IDs, never base64 editor content.
  6. The user reviews fidelity warnings and commits the new work and assets in one transaction or cancels without residue.
Academic source search and citation sequence
  1. The Research drawer searches the local source library first and works offline.
  2. For online discovery, the user explicitly chooses a named provider and confirms the query, title, DOI, ISBN, or author terms being sent.
  3. MetadataSearchProvider requests only selected metadata, handles cancellation/rate limits, and records provider/retrieval provenance.
  4. The user reviews and edits the candidate before saving it as normalized CSL-JSON with a verification state.
  5. Inserting a citation creates a source-ID-based citation node with optional locator/prefix/suffix; it does not paste a formatted string.
  6. The citation processor lazily derives visible citations and bibliography from the complete document context, selected CSL style, and locale.
Private proofing sequence
  1. A debounced plain-text projection and stable document ranges are sent to a proofing worker.
  2. English runs through Harper; Bengali/Hindi run through audited Hunspell-compatible dictionaries and shared deterministic rules.
  3. The worker returns bounded findings with language, rule ID, explanation, replacements, and source range.
  4. Stale findings are discarded when the document revision changes.
  5. The writer chooses apply, ignore once, add to personal dictionary, or disable a rule; text is never changed automatically.

  • Editor transaction state: ProseMirror owns selection and undo history.
  • Phonetic composition state: active Roman token, anchor range, request ID, and candidates are ephemeral; only the chosen native Unicode text is committed to the document.
  • Cross-tab awareness: revision messages through BroadcastChannel; IndexedDB remains authoritative.
  • Network state: metadata searches are ephemeral and provider-labelled; no document text is held by a network facade.
  • Derived state: word counts, reference-excluded counts, bibliography, asset usage, search results, and status labels are recomputed, not duplicated.

Transactional boundaries

  • Saving content updates one document, its work's updatedAt, and its complete asset-reference set in one transaction.
  • Imported/attached asset bytes are validated and hashed before staging; the final document plus reference rows commit atomically, and cancelled staging is cleaned.
  • Reordering chapters updates one book record; no chapter content moves.
  • Deleting an ordered work soft-deletes its metadata and child documents atomically; shared assets are retained until a delayed reachability sweep proves them orphaned.
  • Source edits preserve provider provenance and trigger derived citation/bibliography invalidation; rendered strings are not persisted as authority.
  • Deleting a tag removes assignments only; deleting a source is blocked or converted to an explicit tombstone while citations/notes reference it.
  • Activating a pack flips active versions only after all entries and smoke tests succeed.
  • Library restore validates and stages all bytes first, then applies record/reference changes in bounded Dexie transactions after conflict decisions.

Revision and conflict algorithm

1. Editor opens document at revision N.
2. Save submits expectedRevision = N.
3. Repository reads the current record within the write transaction.
4. If current.revision === N:
     write revision N + 1 and return success.
5. Otherwise:
     preserve incoming content as a new “Conflict copy — timestamp” document,
     return conflict details, and never replace the current record.

manifestCoreHash hashes a documented canonical JSON serialization of the manifest with the entire integrity member omitted, avoiding a self-referential digest. assets.json preserves names, dimensions/duration, creation time, and other validated metadata; the manifest binds each asset ID to its hash-addressed byte entry. Citation clusters remain inside controlled document JSON and bibliographies are always derived. Downloaded language packs, proofing engines/dictionaries, and application-bundled CSL resources are reinstallable product assets and are excluded from user backup unless a later format explicitly defines a licensed portable-resource section.

On restore, normalize and allowlist paths, reject absolute/parent paths, duplicate names, unsupported compression methods, excessive entry counts, oversized compressed or expanded totals, suspicious compression ratios, and mismatched hashes. SHA-256 detects corruption; it is not a signature and does not prove who created an archive.

Never auto-reset a failed database Migration or open failures must enter a read/recovery experience. The application should offer diagnostics and backup export before any “start fresh” operation.

Editor composition policy

  • The phonetic mode is always visible beside the caret/toolbar and has a keyboard shortcut; switching it never rewrites committed content.
  • Candidate generation is token-first for typing latency, with a bounded optional neighboring-token hint used only for ranking—not natural sentence translation.

Normalization and ranking

  1. Validate length and remove control characters except permitted line separators.
  2. Normalize to Unicode NFC; preserve original display input.
  3. Apply language-specific case, punctuation, and known orthographic aliases.
  4. Segment phrases using Intl.Segmenter when supported and a tested fallback otherwise.
  5. Use longest phrase match before individual words.
  6. Rank user memory above curated phrases, then direct entries, aliases, fuzzy matches, pivots, and rules.
  7. Use high/medium/low labels based on deterministic match provenance, not fabricated statistical probability.

Short answer Reuse standards and existing packages for editor/runtime mechanics. Build the smallest internal phonetic-composer adapter and versioned static Bengali/Hindi data packs. Step 5 — Implement revision-safe document persistence 
// dexie-document.repository.ts
import { Injectable } from '@angular/core';

import { db } from './lekhoni.db';
import type { DocumentRepository, SaveResult, WritingDocument } from '../../domain';

@Injectable({ providedIn: 'root' })
export class DexieDocumentRepository implements DocumentRepository {
  get(id: string): Promise<WritingDocument | undefined> {
    return db.documents.get(id);
  }

  save(incoming: WritingDocument, expectedRevision: number): Promise<SaveResult> {
    return db.transaction('rw', db.documents, db.works, db.assetReferences, async () => {
      const current = await db.documents.get(incoming.id);

      if (current && current.revision !== expectedRevision) {
        const now = new Date().toISOString();
        const { work, document: conflict } = createStandaloneConflictCopy(incoming, now);
        await db.works.add(work);
        await db.documents.add(conflict);
        await db.assetReferences.bulkPut(extractAssetIds(conflict.content).map((assetId) => ({
          documentId: conflict.id,
          assetId,
        })));
        return { status: 'conflict', current, conflict };
      }

      const saved = {
        ...incoming,
        revision: expectedRevision + 1,
        updatedAt: new Date().toISOString(),
      };
      await db.documents.put(saved);
      await db.works.update(saved.workId, { updatedAt: saved.updatedAt });
      await db.assetReferences.where('documentId').equals(saved.id).delete();
      await db.assetReferences.bulkPut(extractAssetIds(saved.content).map((assetId) => ({
        documentId: saved.id,
        assetId,
      })));
      return { status: 'saved', document: saved };
    });
  }
}

createStandaloneConflictCopy() creates a new top-level work/document pair that preserves the incoming mode and content, uses new IDs/revision 1, and is immediately visible in the library. Map QuotaExceededError, database-open failures, and transaction aborts to typed application failures. Do not catch them and return false; the UI needs enough information to offer retry, cleanup, recovery, or backup.

async function flushShard(records) {
  const deduplicated = deduplicateAndRank(records);
  const json = JSON.stringify(deduplicated);
  const digest = createHash('sha256').update(json).digest('hex');
  const fileName = `part-${state.shardNumber++}.${digest.slice(0, 16)}.json`;
  await writeFile(`${OUTPUT}/${fileName}`, json, 'utf8');
  state.shards.push({ fileName, bytes: Buffer.byteLength(json), sha256: digest });
}

// language-pack-installer.ts
import { PackEntrySchema, PackManifestSchema } from './schemas';

export async function downloadAndStagePack(manifestUrl: string): Promise<void> {
  const manifestResponse = await fetch(manifestUrl, { cache: 'no-store' });
  if (!manifestResponse.ok) throw new Error('PACK_MANIFEST_DOWNLOAD_FAILED');
  const manifest = PackManifestSchema.parse(await manifestResponse.json());

  for (const shard of manifest.shards) {
    const response = await fetch(new URL(shard.url, manifestUrl));
    if (!response.ok) throw new Error('PACK_SHARD_DOWNLOAD_FAILED');

    const bytes = new Uint8Array(await response.arrayBuffer());
    if (bytes.byteLength !== shard.bytes) throw new Error('PACK_SIZE_MISMATCH');
    if (await sha256(bytes) !== shard.sha256.toLowerCase()) {
      throw new Error('PACK_HASH_MISMATCH');
    }

    const raw = JSON.parse(new TextDecoder().decode(bytes));
    const entries = PackEntrySchema.array().parse(raw);
    await languagePackRepository.stage(manifest.pair, manifest.version, entries);
  }

  await runGoldenSmokeQueries(manifest.pair, manifest.version);
  await languagePackRepository.activate(manifest.pair, manifest.version);
}

  if (format === 'docx') {
    const assets: StagedImportAsset[] = [];
    const result = await mammoth.convertToHtml(
      { arrayBuffer: bytes },
      {
        includeDefaultStyleMap: true,
        convertImage: mammoth.images.imgElement(async (image) => {
          const stagingId = crypto.randomUUID();
          assets.push({
            stagingId,
            mimeType: image.contentType,
            bytes: decodeBase64(await image.read('base64')),
          });
          return {
            src: `about:blank#${stagingId}`,
            'data-lekhoni-import-asset': stagingId,
            alt: '',
          };
        }),
      },
    );
    return {
      html: result.value,
      warnings: result.messages.map((message) => `${message.type}: ${message.message}`),
      assets,
    };
  }

  const text = new TextDecoder('utf-8', { fatal: true }).decode(bytes);
  if (format === 'markdown') {
    return {
      html: await marked.parse(text, { async: true, gfm: true }),
      warnings: [],
      assets: [],
    };
  }
  if (format === 'html') return { html: text, warnings: [], assets: [] };

  const html = text
    .split(/\r?\n\s*\r?\n/)
    .map((paragraph) => `<p>${escapeHtml(paragraph).replace(/\r?\n/g, '<br>')}</p>`)
    .join('');
  return { html, warnings: [], assets: [] };
}

function decodeBase64(value: string): ArrayBuffer {
  const binary = atob(value);
  const bytes = new Uint8Array(binary.length);
  for (let index = 0; index < binary.length; index += 1) {
    bytes[index] = binary.charCodeAt(index);
  }
  return bytes.buffer;
}

function escapeHtml(value: string): string {
  return value
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;');
}

// archive-writer.ts
import { AsyncZipDeflate, Zip } from 'fflate';

export interface ArchiveEntrySource {
  path: string;
  bytes: AsyncIterable<Uint8Array>;
  maxBytes: number;
}

export function writeArchive(entries: AsyncIterable<ArchiveEntrySource>): Promise<Blob> {
  return new Promise((resolve, reject) => {
    const output: Uint8Array[] = [];
    const zip = new Zip((error, chunk, final) => {
      if (error) {
        reject(error);
        return;
      }
      output.push(chunk);
      if (final) resolve(new Blob(output, { type: 'application/zip' }));
    });

    void (async () => {
      try {
        for await (const entry of entries) {
          assertSafeArchivePath(entry.path);
          const file = new AsyncZipDeflate(entry.path, { level: 6 });
          zip.add(file);

          let written = 0;
          for await (const chunk of entry.bytes) {
            written += chunk.byteLength;
            if (written > entry.maxBytes) throw new Error('ARCHIVE_ENTRY_TOO_LARGE');
            file.push(chunk, false);
          }
          file.push(new Uint8Array(), true);
        }
        zip.end();
      } catch (error) {
        zip.terminate();
        reject(error);
      }
    })();
  });
}

export function assertSafeArchivePath(path: string): void {
  if (path.includes('\\') || path.startsWith('/') || /^[a-zA-Z]:/.test(path)) {
    throw new Error('UNSAFE_ARCHIVE_PATH');
  }
  const segments = path.split('/');
  if (segments.some((segment) => !segment || segment === '.' || segment === '..')) {
    throw new Error('UNSAFE_ARCHIVE_PATH');
  }
  if (!/^(manifest\.json|records\/[a-z0-9._-]+\.json|assets\/[a-f0-9]{64}\.[a-z0-9]+)$/i.test(path)) {
    throw new Error('UNEXPECTED_ARCHIVE_PATH');

}
// archive-reader.ts
import { AsyncUnzipInflate, Unzip } from 'fflate';

const LIMITS = {
  entries: 10_100,
  entryBytes: 250_000_000,
  totalExpandedBytes: 1_000_000_000,
  compressionRatio: 100,
} as const;

export interface ArchiveEntrySink {
  write(chunk: Uint8Array): Promise<void>;
  close(): Promise<void>;
}

export function readArchive(
  blob: Blob,
  openSink: (path: string, expectedBytes: number) => Promise<ArchiveEntrySink>,
): Promise<void> {
  return new Promise((resolve, reject) => {
    let entryCount = 0;
    let expandedTotal = 0;
    let pending = 0;
    let inputComplete = false;
    let failed = false;

    const fail = (error: unknown) => {
      if (failed) return;
      failed = true;
      reject(error);
    };
    const finishIfReady = () => {
      if (!failed && inputComplete && pending === 0) resolve();
    };

    const unzip = new Unzip((file) => {
      try {
        entryCount += 1;
        if (entryCount > LIMITS.entries) throw new Error('ARCHIVE_ENTRY_LIMIT');
        assertSafeArchivePath(file.name);
        if (file.originalSize > LIMITS.entryBytes) throw new Error('ARCHIVE_ENTRY_TOO_LARGE');
        if (file.size > 0 && file.originalSize / file.size > LIMITS.compressionRatio) {
          throw new Error('ARCHIVE_RATIO_LIMIT');
        }
        expandedTotal += file.originalSize;
        if (expandedTotal > LIMITS.totalExpandedBytes) throw new Error('ARCHIVE_TOTAL_LIMIT');
      } catch (error) {
        fail(error);
        return;
      }

      pending += 1;
      void openSink(file.name, file.originalSize).then((sink) => {
        let received = 0;
        let writes = Promise.resolve();
        file.ondata = (error, chunk, final) => {
          if (error) return fail(error);
          received += chunk.byteLength;
          if (received > LIMITS.entryBytes || received > file.originalSize) {
            return fail(new Error('ARCHIVE_EXPANDED_SIZE_MISMATCH'));
          }
          writes = writes
            .then(() => sink.write(chunk))
            .then(async () => {
              if (!final) return;
              if (received !== file.originalSize) throw new Error('ARCHIVE_TRUNCATED_ENTRY');
              await sink.close();
              pending -= 1;
              finishIfReady();
            });
          void writes.catch(fail);
        };
        file.start();
      }).catch(fail);
    });

    unzip.register(AsyncUnzipInflate);
    void (async () => {
      const reader = blob.stream().getReader();
      while (!failed) {
        const { value, done } = await reader.read();
        if (done) break;
        unzip.push(value, false);
      }
      inputComplete = true;
      unzip.push(new Uint8Array(), true);
      finishIfReady();
    })().catch(fail);
  });
}

The restore pipeline writes entries to bounded staging storage, validates manifest.json first, checks every declared byte count and SHA-256 digest, validates each JSON record with Zod, previews conflicts, and only then opens write transactions. It never trusts a filename, MIME value, or compressed size from the ZIP alone.

function mapHarperLint(
  lint: Lint,
  text: string,
  documentOffset: number,
  revision: number,
): ProofingFinding {
  const span = lint.span();
  const localFrom = scalarIndexToUtf16(text, span.start);
  const localTo = scalarIndexToUtf16(text, span.end);
  const suggestions = lint.suggestions();
  const replacements = suggestions
    .slice(0, 5)
    .map((suggestion) => suggestion.get_replacement_text());
  const kind = lint.lint_kind();

  const finding: ProofingFinding = {
    id: crypto.randomUUID(),
    revision,
    language: 'en',
    category: harperCategory(kind),
    ruleId: `harper:${kind}`,
    severity: 'suggestion',
    from: documentOffset + localFrom,
    to: documentOffset + localTo,
    originalText: text.slice(localFrom, localTo),
    message: lint.message(),
    replacements,
    provenance: 'harper',
  };

  suggestions.forEach((suggestion) => suggestion.free());
  span.free();
  lint.free();
  return finding;
}

function scalarIndexToUtf16(value: string, scalarIndex: number): number {
  let scalar = 0;
  let utf16 = 0;
  for (const character of value) {
    if (scalar === scalarIndex) return utf16;
    scalar += 1;
    utf16 += character.length;
  }
  return utf16;
}

function harperCategory(kind: string): ProofingFinding['category'] {

  if (kind === 'Grammar' || kind === 'Agreement' || kind === 'WordOrder') return 'grammar';
  if (kind === 'Punctuation' || kind === 'Capitalization') return 'punctuation';
  if (kind === 'Repetition') return 'repetition';
  return 'style';
}

  | { id: string; type: 'add-word'; language: NativeLanguage; word: string };

function checkNativeSpelling(
  spell: SpellChecker,
  request: Extract<SpellingWorkerRequest, { type: 'check' }>,
): ProofingFinding[] {
  const segmenter = new Intl.Segmenter(request.language, { granularity: 'word' });
  const requiredScript = request.language === 'bn' ? /\p{Script=Bengali}/u : /\p{Script=Devanagari}/u;
  const findings: ProofingFinding[] = [];

  for (const segment of segmenter.segment(request.text)) {
    const word = segment.segment;
    const lookupWord = word.normalize('NFC');
    if (!segment.isWordLike || !requiredScript.test(lookupWord) || spell.correct(lookupWord)) continue;
    findings.push({
      id: crypto.randomUUID(),
      revision: request.revision,
      language: request.language,
      category: 'spelling',
      ruleId: `nspell:${request.language}`,
      severity: 'suggestion',
      from: request.documentOffset + segment.index,
      to: request.documentOffset + segment.index + word.length,
      originalText: word,
      message: 'This word is not in the installed spelling dictionary.',
      replacements: spell.suggest(lookupWord).slice(0, 5),
      provenance: 'hunspell',
    });
    if (findings.length >= 500) break;
  }
  return findings;
}

import { Injectable, computed, inject, signal } from '@angular/core';

import {
  EDITOR_ADAPTER,
  PHONETIC_INPUT_ENGINE,
} from '../../core/infrastructure.tokens';
import type {
  CompositionSession,
  PhoneticCandidate,
  PhoneticInputMode,
} from '../../domain/models';

type CompositionDraft = Omit<CompositionSession, 'id' | 'candidates'>;

@Injectable()
export class UnicodeComposerFacade {
  private readonly engine = inject(PHONETIC_INPUT_ENGINE);
  private readonly editor = inject(EDITOR_ADAPTER);
  private requestSequence = 0;
  private pending?: AbortController;

  readonly mode = signal<PhoneticInputMode>('native');
  readonly session = signal<CompositionSession | null>(null);
  readonly loading = signal(false);
  readonly candidates = computed(() => this.session()?.candidates ?? []);

  setMode(mode: PhoneticInputMode): void {
    this.cancel();
    this.mode.set(mode);
  }

  async updateRomanToken(draft: CompositionDraft): Promise<void> {
    if (this.mode() === 'native' || draft.mode !== this.mode() || !draft.romanText.trim()) {
      this.cancel();
      return;
    }

    this.pending?.abort();
    this.pending = new AbortController();
    const requestId = ++this.requestSequence;
    this.loading.set(true);

    try {
      const candidates = await this.engine.suggest({
        language: draft.mode === 'bn-phonetic' ? 'bn' : 'hi',
        romanText: draft.romanText,
        limit: 8,
      }, this.pending.signal);

      if (requestId !== this.requestSequence || this.pending.signal.aborted) return;
      this.session.set({
        ...draft,
        id: crypto.randomUUID(),
        candidates,
      });
    } catch (error) {
      if (error instanceof DOMException && error.name === 'AbortError') return;
      throw error;
    } finally {
      if (requestId === this.requestSequence) this.loading.set(false);
    }
  }

  commit(candidate: PhoneticCandidate): boolean {
    const session = this.session();
    if (
      !session
      || candidate.romanText !== session.romanText
      || !session.candidates.some((item) => item.id === candidate.id)
    ) return false;
    const committed = this.editor.commitComposition(
      session,
      candidate.nativeText.normalize('NFC'),
      candidate.language,
    );
    if (committed) this.cancel();
    return committed;
  }

  keepRoman(): boolean {
    const session = this.session();
    if (!session) return false;
    const language = session.mode === 'bn-phonetic' ? 'bn-Latn' : 'hi-Latn';
    const committed = this.editor.commitComposition(session, session.romanText, language);
    if (committed) this.cancel();
    return committed;
  }

  cancel(): void {
    this.pending?.abort();
    this.pending = undefined;
    this.requestSequence += 1;
    this.loading.set(false);
    this.session.set(null);
  }
}

The editor integration owns token boundaries and the caret popup. It calls updateRomanToken() without inserting the Roman token into canonical content, then calls commit() or keepRoman(). commitComposition() must verify document ID, revision, anchor range, and active token before dispatching one ProseMirror transaction.

@Injectable({ providedIn: 'root' })
export class BrowserNativeShareService implements NativeContentShareService {
  private readonly downloads = inject(BROWSER_DOWNLOAD_SERVICE);

  canShareText(): boolean {
    return window.isSecureContext && typeof navigator.share === 'function';
  }

  canShareFile(file: File): boolean {
    return this.canShareText()
      && typeof navigator.canShare === 'function'
      && navigator.canShare({ files: [file] });
  }

  async copyText(text: string): Promise<void> {
    if (!window.isSecureContext || !navigator.clipboard?.writeText) {
      throw new Error('CLIPBOARD_UNAVAILABLE');
    }
    await navigator.clipboard.writeText(text.normalize('NFC'));
  }

  async share(request: NativeShareRequest): Promise<ShareOutcome> {
    const text = request.text.normalize('NFC');
    const data: ShareData = { title: request.title, text };
    if (request.file && this.canShareFile(request.file)) data.files = [request.file];

    const canSharePayload = request.file
      ? this.canShareFile(request.file)
      : this.canShareText();
    if (canSharePayload) {
      try {
        await navigator.share(data);
        return 'shared';
      } catch (error) {
        if (error instanceof DOMException && error.name === 'AbortError') return 'cancelled';
        // Capability/runtime failures continue to explicit local fallbacks.
      }
    }

    if (request.file) {
      this.downloads.download(request.file, request.file.name);
      return 'downloaded';
    }

    try {
      await this.copyText(text);
      return 'copied';
    } catch {
      return 'manual-copy';
    }
  }
}

Deterministic multilingual rules

Low-risk typography

Repeated spaces, spaces before punctuation, repeated punctuation, unmatched brackets/quotes, and inconsistent line-ending characters.

Repetition

Adjacent duplicate tokens after script-aware normalization, excluding a reviewed allowlist and intentional poetic repetition.

Unicode hygiene

Unexpected controls, isolated combining marks, suspicious zero-width characters, mixed normalization, and invalid replacement characters—with no silent normalization of prose.

Every custom rule has positive/negative fixtures for English, Bengali, Hindi, poems, code blocks, URLs, citations, names, and intentional repetition. Code blocks, citation output, bibliography nodes, URLs, and user-excluded ranges are not proofread by default.

Worker and editor integration

  1. Derive plain text and a stable offset map from supported text nodes; do not send ProseMirror JSON to a third party.
  2. Debounce checks independently from autosave and cancel an older request as soon as the revision changes.
  3. Lazy-load Harper and only the active Bengali/Hindi dictionary in proofing.worker.ts.
  4. Return a bounded number of findings per pass; decorate ranges through editor transactions that are excluded from undo history.
  5. Before applying a suggestion, verify the revision and original range text. If either changed, discard and rerun.
  6. Persist personal dictionary entries, disabled rule IDs, and explicit ignore-all decisions; keep ignore-once in memory.

Dictionary and legal gate

  • Audit Bengali and Hindi Hunspell candidates independently for license, source revision, maintainer, encoding, affix compatibility, offensive content, and spelling quality.
  • Keep the dictionary data's license and attribution separate from the MIT-licensed nspell engine.
  • Run native-review corpora containing common words, inflections, proper names, regional variants, conjuncts/matras, and intentional code switching.
  • If either dictionary fails legal or quality review, ship deterministic writing checks for that language and label dictionary spelling as unavailable rather than substituting an online service.

Asset lifecycle

  1. Inspect extension, declared MIME, magic bytes, byte count, image dimensions, and media metadata before accepting a file.
  2. Decode images in a bounded path to reject malformed/decompression-bomb dimensions; SVG is excluded from v1 because it can carry active content.
  3. Compute SHA-256 with Web Crypto, deduplicate by hash, and compare the projected total with navigator.storage.estimate().
  4. Store original bytes as an IndexedDB Blob; store only asset IDs and presentation metadata in ProseMirror JSON.
  5. Create object URLs only while a node is mounted and revoke them on node removal, document switch, and component destruction.
  6. Track references transactionally and delete proven orphans only after a grace period and recovery/backup checks.

Citation model and processing

  1. A citation node stores a stable cluster of source IDs and cite-item attributes such as locator, label, prefix, suffix, and suppress-author.
  2. The selected CSL style and locale belong to the work, not to individual markers. Academic templates require and initialize them; another mode creates them only when its writer enables citations.
  3. The processor receives the ordered citation clusters and complete source set so numeric ordering, disambiguation, repeated citations, note styles, and bibliography sorting use document context.
  4. Formatted output is sanitized and cached only by document revision + source revisions + style/locale version; source IDs remain the authority.
  5. Changing metadata or style invalidates derived output and updates every marker/bibliography consistently without rewriting prose.
  6. Missing/deleted sources, unsupported CSL fields, and formatter failures display visible placeholders and block a clean academic export.

CSL and citation package policy

  • Use @citation-js/core with BibTeX/RIS/CSL plugins for format normalization and a CSL/citeproc engine for rendering; never hand-code APA/MLA/Chicago/IEEE punctuation.
  • Bundle a reviewed small starter set such as APA, MLA, Chicago author-date, IEEE, and a generic Harvard style plus required locales. Record exact upstream revisions and golden outputs.
  • Preserve CSL style authors/contributors and show clear CSL Project attribution/link as required by the style repository's CC BY-SA license.
  • The transitive citeproc CPAL/AGPL choice and source/attribution obligations must be approved before release. If not approved, keep the CitationProcessor port and replace the implementation; do not ship an unreviewed formatter.
  • Sanitize formatter HTML even though inputs are structured metadata, and allow only the inline/block elements and classes required for CSL output.

Research notes and tags

Evidence-aware notes

Each note is explicitly classified as quote, paraphrase, summary, or idea and may link to one source, locator, work, and multiple tags. Quote text is never converted into a paraphrase automatically.

Reusable organization

Tags apply to works, documents, sources, and notes. Filters can combine type, tag, author, year, verification state, and cited/uncited state without duplicating entities.

Source deletion is referentially safe: cited or noted sources cannot disappear silently. The UI offers cancel, replace references, or retain a tombstone with the last known metadata. Removing a tag never removes its targets.

  • Show total words, prose words excluding bibliography/citation output, words by section, source count, cited/uncited sources, unverified metadata count, and broken-reference count.
  • Assignment targets are guidance only; no score or authorship claim is inferred.
  • Lekhoni does not claim that a citation proves a statement, that a source is credible, or that a paper is plagiarism-free.
  • Do not rank sources by citation count as quality. Provider metrics, if shown, are labelled, dated, optional, and never used as an automatic recommendation.
  • No hidden AI generation, summarization, literature-review writing, or document upload exists in v1.0.

Creating/editing sources, importing/exporting bibliographies, local search, citations, bibliography formatting, notes, tags, and all writing work offline after their lazy chunks/styles/locales have been installed. Export orchestration

// document-export.service.ts
export class DefaultDocumentExportService implements DocumentExportService {
  constructor(
    private readonly source: ExportSourceRepository,
    private readonly mapper: ProseMirrorExportMapper,
    private readonly renderers: readonly ExportRenderer[],
    private readonly printPreview: PrintPreviewService,
    private readonly downloads: BrowserDownloadService,
  ) {}

  async export(request: ExportRequest): Promise<ExportResult> {
    const source = await this.source.loadConsistentSnapshot(request.scope, request.sourceId);
    const document = await this.mapper.map(source, request.options);

    if (request.format === 'pdf') {
      const jobId = await this.printPreview.createJob(document, request.options);
      return { kind: 'print-preview', jobId };
    }

    const renderer = this.renderers.find((item) => item.format === request.format);
    if (!renderer) throw new Error(`UNSUPPORTED_EXPORT_FORMAT:${request.format}`);

    const rendered = await renderer.render(document, request.options);
    const fileName = createSafeFileName(document.title, rendered.extension);
    this.downloads.download(rendered.blob, fileName);
    return {
      kind: 'download',
      fileName,
      bytes: rendered.blob.size,
      fidelity: rendered.fidelity,
    };
  }
}

The source repository must read a consistent saved revision. If the editor is dirty, the user is prompted to save or intentionally export the current in-memory draft. Export never changes the stored writing.

Safe browser downloads

// blob-download.service.ts
export class BlobDownloadService implements BrowserDownloadService {
  download(blob: Blob, requestedName: string): void {
    const fileName = sanitizeFileName(requestedName);
    const url = URL.createObjectURL(blob);
    const anchor = document.createElement('a');
    anchor.href = url;
    anchor.download = fileName;
    anchor.hidden = true;
    document.body.append(anchor);
    anchor.click();
    anchor.remove();

    // Keep the URL alive long enough for browsers that begin the download asynchronously.
    window.setTimeout(() => URL.revokeObjectURL(url), 30_000);
  }
}

function sanitizeFileName(value: string): string {
  const cleaned = value
    .normalize('NFC')
    .replace(/[<>:"/\\|?*\u0000-\u001F]/g, '-')
    .replace(/[. ]+$/g, '')
    .trim()
    .slice(0, 120);
  const fallback = cleaned || 'Untitled';
  return /^(con|prn|aux|nul|com[1-9]|lpt[1-9])(?:\.|$)/i.test(fallback)
    ? `_${fallback}`
    : fallback;
}

The download filename is a browser hint and may be adjusted by the operating system. Object URLs are always revoked to prevent memory leaks.

DOCX export with the docx package

The exporter is dynamically imported only after the user selects DOCX, keeping it outside the initial writing bundle. Direct neutral-tree mapping is preferred over arbitrary HTML conversion because it gives controlled structure and predictable loss reporting.

// docx-export.renderer.ts
export class DocxExportRenderer implements ExportRenderer {
  readonly format = 'docx' as const;

  async render(model: ExportDocument, options: ExportOptions): Promise<RenderedExport> {
    const docx = await import('docx');
    const children: Array<
      InstanceType<typeof docx.Paragraph> | InstanceType<typeof docx.Table>
    > = [];

    children.push(new docx.Paragraph({
      text: model.title,
      heading: docx.HeadingLevel.TITLE,
      alignment: docx.AlignmentType.CENTER,
    }));

    model.sections.forEach((section, sectionIndex) => {
      children.push(new docx.Paragraph({
        text: section.title,
        heading: docx.HeadingLevel.HEADING_1,
        pageBreakBefore: options.sectionPageBreaks && sectionIndex > 0,
        keepNext: true,
      }));

      for (const block of section.blocks) {
        children.push(...mapBlockToDocx(block, model.assets, docx));
      }
    });

    const document = new docx.Document({
      creator: model.author || 'Lekhoni writer',
      title: model.title,
      description: 'Exported from Lekhoni',
      sections: [{
        properties: pageProperties(options),
        children,
      }],
    });

    const blob = await docx.Packer.toBlob(document);
    return {
      blob,
      extension: 'docx',
      mediaType: blob.type,
      fidelity: buildExportFidelityReport(model, 'docx'),
    };
  }
}

function mapPoemLine(block: Extract<ExportBlock, { type: 'poem-line' }>, docx: typeof import('docx')) {

    children: mapInlineRuns(block.children, docx),
    spacing: { before: block.stanzaStart ? 240 : 0, after: 0, line: 280 },
    keepLines: true,
  });
}

  1. User opens Export from the editor or work menu.
  2. Dialog announces scope and defaults to the current document; Complete work is available for any work and includes ordered child sections when present.
  3. User chooses PDF, Word (.docx), HTML, Markdown, or Text.
  4. Optional settings are progressively disclosed by format.
  5. A compatibility note explains PDF print flow or DOCX font substitution.
  6. Progress is announced through a polite live region; Cancel uses AbortController where possible.
  7. On success, the app announces the downloaded filename or moves to print preview. On failure, it preserves editing state and offers retry.

Security, privacy, and accessibility rules

  • File generation and clipboard copy are entirely local. Web Share transfers only the previewed payload after an explicit user action to the browser/OS target selected by the user.
  • Render from validated JSON and escaped text; never export innerHTML from the live editor.
  • Standalone HTML contains no script, iframe, form, remote analytics, event attribute, or unsafe URL scheme.
  • Resolve every asset ID against the validated asset store; missing/hash-mismatched assets produce a visible preflight error rather than a broken silent export.
  • Recompute citation clusters and bibliography from source IDs, work style/locale, and full ordered context immediately before export.
  • DOCX generation never enables macros, OLE attachments, remote templates, or external relationships in v1.0.
  • PDF/HTML headings, lists, tables, figures, captions, and notes remain semantic where the target supports them; DOCX uses native structures where reliable.
  • File actions use buttons with explicit format names and announce that a download, print dialog, or external office application may open.
  • For the most accessible distribution, recommend HTML or DOCX; browser-created PDF tagging varies and must not be overstated.

  • Academic citation goldens, source verification, broken-reference preflight, and offline research workflows pass.

  • Performance and memory budgets pass.
  • No critical/serious accessibility violation remains.

No-go triggers

  • Any reproducible loss or silent overwrite of writing.
  • Unknown or non-distributable language-data provenance.
  • App update clears or prevents access to stored work.
  • Backup cannot restore records and binary assets to a fresh browser profile, or accepts an unsafe/mismatched archive.
  • Language UI implies natural translation it does not provide.
  • The composer silently guesses Bengali versus Hindi, commits a stale candidate, requires more than one Undo, corrupts a grapheme, or stores Roman text when native text was selected.
  • Share sends content without an explicit preview/user action or produces a payload different from the preview.
  • Proofing UI implies full Bengali/Hindi grammar or automatically changes prose.
  • Citation processor/style/dictionary/import dependency licensing or attribution is unresolved.
  • Imported active content can execute, an asset bypasses policy, or a stale/broken citation exports silently.
  • Core operation cannot be completed by keyboard.
  • Production sends writing, titles, assets, notes, local sources, proofing text, or lookup content externally, or performs an unconfirmed metadata request.
  • Representative mobile browser exceeds the hard memory gate.

Future architecture

The MVP deliberately establishes ports that permit growth without replacing the editor or domain model.

Optional ASP.NET sync

A future ASP.NET Core API can implement authentication, encrypted backup, multi-device synchronization, conflict history, and sharing through a RemoteDocumentRepository.

The local repository remains first-class for offline use; a sync coordinator exchanges operations or revisions when authenticated.

Natural translation

A future ContextualTranslationEngine may use a managed provider, self-hosted model, or proven on-device browser model. It must remain distinct from deterministic dictionary lookup.

Users must opt in before document text leaves the device.

Advanced publishing

EPUB, publishing-platform integrations, custom templates, professional typesetting, and direct tagged-PDF generation can implement additional ExportRenderer ports without changing stored content.

Collaboration

Real-time collaboration requires identity, authorization, a CRDT/OT design, and server persistence; it is not an incremental toggle.

Research integrations

Library catalogs, ORCID, Zotero-compatible exchange, open-access lookup, and institution proxies require separate provider/authorization/privacy reviews and continue to normalize through SourceRecord.

Advanced proofing

Any future Bengali/Hindi grammar or AI writing engine must implement ProofingEngine, prove language quality, expose provenance, preserve explicit apply/undo, and obtain opt-in before any text leaves the device.

Final implementation decisions

  • The primary USP is explicit Bengali/Hindi phonetic typing: Roman input at the caret becomes user-confirmed native Unicode inside every writing mode.
  • Canonical writing stores NFC Bengali/Devanagari text plus language metadata—not Roman source tokens, glyph images, or Bijoy/Krutidev-style legacy encodings.
  • Native Unicode can be copied, shared through the user-controlled Web Share target chooser, or exported to PDF, DOCX, HTML, Markdown, and UTF-8 text with capability fallbacks.
  • Angular 22 standalone PWA; no backend in v1.0.
  • Anonymous local-first use with Dexie/IndexedDB.
  • Five workspaces: Document, Book, Poem, Essay, and a distinct Academic/Research mode with templates.
  • Controlled ProseMirror JSON through an ngx-editor adapter, extended with tables, figures, media cards, citations, notes, and bibliography—not executable arbitrary HTML.
  • Binary files are validated/deduplicated IndexedDB Blobs referenced by asset IDs, never base64 editor content.
  • Angular Signals and facades; no NgRx for MVP complexity.
  • Angular service worker rather than a second Workbox pipeline.
  • Versioned, hash-verified .lekhoni ZIP archive for records and binary assets with strict path/count/size/ratio/time controls.
  • DOCX/HTML/Markdown/text import always passes through worker limits, sanitization, controlled-schema mapping, and an explicit fidelity report.
  • PDF through semantic browser print preview; DOCX through a lazy docx adapter; HTML/Markdown through strict local serializers with asset packages where required.
  • Academic sources normalize to CSL-JSON; citation nodes store source references and bibliography/citation strings are derived from complete context.
  • Crossref is the first explicit metadata provider; OpenAlex remains optional behind terms/CORS/usage validation. No API key is baked into the public frontend.
  • English grammar/spelling uses local Harper; Bengali/Hindi use separately audited spelling dictionaries plus conservative deterministic rules, not a full-grammar claim.
  • Sharded JSON language packs first; optimize format only after profiling.
  • Language work happens in a Web Worker.
  • Wiktionary/Aksharantar data only after provenance/license gates.
  • No hidden runtime API, automatic content upload, network transliteration fallback, or fabricated sentence translation; only confirmed provider-labelled scholarly metadata queries and explicit user-previewed Web Share payloads may leave the application.
  • Azure Static Web Apps is the default deployment target, replaceable by any compliant static CDN.
  • Privacy-first launch with no third-party analytics SDK.
Implementation starting point Begin with the USP spike—not feature volume. Prove Roman Bengali and Hindi composition at the editor caret, native-reviewed candidate quality, one-step commit/undo, NFC/grapheme correctness, and exact copy/Web Share/export portability on target browsers. Only then expand the broader editor, persistence, import, research, proofing, and dictionary features.
